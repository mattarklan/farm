## What This Project Is

A rules-based autonomous farm management system written in Python. Sensor readings flow into a SQLite database, a pipeline processes them through event detection, rule matching, constraint filtering, and execution. All decision logic lives in YAML config files — Python is purely the execution kernel. There is no UI yet; that comes later (SCADA/HMI phase).

---

## Architecture Overview

```
SensorStore (SQLite)
       ↓
  StateBuilder         ← builds system state from latest DB readings
       ↓
  EventEngine          ← fires typed events when sensor thresholds are breached
       ↓
  RuleEngine           ← maps events → actions via rules.yaml
       ↓
  ConstraintEngine     ← filters actions (block / delay / allow)
       ↓
  Executor             ← carries out safe actions
       ↓
  DecisionMemory       ← records events, blocked actions, results
       ↓
  Logger               ← saves full state snapshots to farm_log.json
```

All of the above is orchestrated by `Pipeline.run(state)` in `core/pipeline.py`.

## What Was Built This Session

### 1. Core Pipeline
Built and wired together the full pipeline from scratch:
- `FarmEngine` → `Pipeline` → all sub-engines
- `Pipeline.run(state)` returns a result dict with events, actions, allowed, blocked, delayed, results

### 2. Asset Registry (`loader.py`)
- Loads `water.yaml` into a `Registry` object
- Builds a `sensor_index` mapping sensor IDs → parent assets
- `get_asset_from_sensor(sensor_id)` used by EventEngine to look up asset type

### 3. SQLite Sensor Store (`sensor_store.py`)
- `record(sensor_id, value, timestamp)` — writes a reading
- `latest_readings()` — returns the most recent reading per sensor
- `StateBuilder` now reads from DB instead of hardcoded values
- DB is created at `farm.db` in the project root automatically

### 4. Event Engine (`event_engine.py`)
- Matches sensor readings against rules in `events.yaml`
- Matches on `asset_type` and `sensor_suffix`
- Evaluates conditions with lt / lte / gt / gte / eq operators
- Confirmed working: `E_TANK_LOW` fired correctly on `tank_1_level = 15.0`

### 5. Constraint Engine (`constraint_engine.py`)
- Evaluates actions against safety rules in `constraints.yaml`
- Returns three buckets: allowed, blocked, delayed
- Supports battery SOC and water pressure conditions
- `evaluate(actions, state, derived)` is the entry point

### 6. Asset Registry Expanded (`water.yaml`)
- Added 2 header tanks, rain harvesting asset, 4 growing zones
- Added GPS coordinates to all assets (placeholder Perth-area coords — update to real)
- Added zone assets (capsicum A/B, tomato A/B) with soil moisture and flow sensors

### 7. Rules Expanded (`rules.yaml`)
Added rules covering:
- Zone irrigation (capsicum, tomato) triggered by soil moisture events

- Tank balancing
- Tank full → close bore valves
- Low and critical battery load shedding

## Mistakes and Changes of Mind

### Mixed tabs and spaces
Happened multiple times across `engine.py`, `constraint_engine.py`, and `test.py`. Python 3 treats these as `IndentationError` or silent logic bugs. Always use 4 spaces. Configure your editor to show whitespace characters.

### Circular self-import in `constraint_engine.py`
The file had `from core.constraint_engine import ConstraintEngine` at the top of itself. Removed entirely — a file never needs to import itself.

### `__dict__` on slotted dataclasses
`Logger` used `state.__dict__` to serialize state, but state classes used `__slots__`, which have no `__dict__`. Fixed by using `dataclasses.asdict()` plus a recursive `json_serializable()` helper to handle nested `datetime` objects.

### `datetime.utcnow()` deprecated
Replaced with `datetime.now(timezone.utc)` throughout. Python 3.12+ warns on `utcnow()` and it will be removed in a future version.

### `RuleEngine` missing `rules_config` argument
`FarmEngine` was instantiating `RuleEngine()` with no arguments. Fixed by loading `config/rules.yaml` with PyYAML in `engine.py` and passing it in. The config file is YAML not JSON — use `yaml.safe_load()`, not `json.load()`.

### PyYAML installed to wrong Python
Machine has both Python 3.12 and 3.13. `pip install pyyaml` went to 3.12 but the project runs on 3.13. Fix: `py -3.13 -m pip install pyyaml`.

### `build_indexes()` called inside loop
In `loader.py`, `registry.build_indexes()` was being called on every asset instead of once after all assets were loaded. Minor performance fix — moved it outside the loop.

### Seed data placed before `db` was created
In `test.py`, `db.record(...)` calls were placed above `db = SensorStore(...)`. Python executes top to bottom — always instantiate before calling methods on an instance.

### `StateBuilder.build()` signature changed mid-session
Originally `build(registry)`, later updated to `build(db, registry)` when DB integration was added. `test.py` wasn't updated at the same time, causing a `TypeError`. Keep `test.py` in sync when changing component signatures.

### `farm/config/...` path prefix
Running from `C:\Users\Matt\Desktop\farm\`, all config paths should be relative to that directory. Several times paths were prefixed with `farm/` (e.g. `farm/config/events.yaml`) which caused `FileNotFoundError`. Correct paths are `config/events.yaml`, `config/registry/water.yaml`, etc.

5. **Add energy.yaml** to the registry covering battery SOC, solar input, and load sensors.

6. **Scheduler** — wrap `pipeline.run(state)` in a loop with a configurable interval (e.g. every 60 seconds) so it runs autonomously rather than being triggered manually.

7. **Derived metrics** — `DerivedEngine` and `RollingWindowStore` are scaffolded but not producing output yet. Implement rolling average, rate-of-change, and trend detection per sensor.

8. **Error handling** — no try/except around DB reads, YAML loads, or pipeline steps. A single bad sensor reading or missing config key will crash the whole loop.

9. **SCADA/HMI interface** — deferred deliberately. Build this after the control loop is stable.
